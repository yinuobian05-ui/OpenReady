# OpenReady v0.2.1

Release date: 2026-08-27.

The npm package, annotated Git tag, and GitHub Release were independently verified after publication.

## Purpose

v0.2.1 shortens the path from a fixed synthetic demo that does not scan the current directory to one privacy-safe observation and, optionally, a real scan of a repository the tester is authorized to inspect.

## Safe first run

Requirements: Node.js 20 or newer and a trusted local Git installation.

```sh
npx --yes "@yb5/openready@0.2.1" demo
```

The demo creates only fixed fictional files in a unique operating-system temporary directory, scans them locally without telemetry, removes that exact directory, and exits `0` when the expected synthetic `BLOCKED` result and cleanup both succeed.

After completion, the CLI prints one copy-ready command for scanning an authorized repository. It does not start that scan automatically.

## Changes

- Add an authorized-repository scan command to the successful demo footer.
- Reduce the README first-run flow to the demo, its expected result, the optional real scan, and one structured feedback form asking for a specific observation plus verification details.
- Add a structured first-run feedback form with explicit privacy boundaries.
- Remove the outdated v0.1.1 recording from the v0.2.x first-run instructions.
- Include the post-v0.2.0 CI pinning, least-privilege workflow example, and future npm staging safeguards already merged on `main`.

The scanner, rule set, JSON contract, exit codes, runtime dependency count, telemetry behavior, and symlink boundaries are unchanged.

## Pre-release verification

- The complete local suite reported 57 tests: 56 passed, 0 failed, and 1 platform-limited skip.
- Package dry-run and the final local tarball contained the same 23 intended files.
- A fresh local tarball install reported version `0.2.1`, completed the synthetic demo and cleanup, printed the v0.2.1 authorized-scan command and feedback-form link, and returned `READY` with 0 blockers, 0 warnings, and 1 informational finding when scanning its installed package directory.
- A clean Git archive snapshot of the release commit returned `READY` with 0 blockers, 6 warnings, and 4 informational findings.

The active checkout itself is not recorded as `READY`: its local Git configuration enables linked-worktree configuration, which OpenReady rejects by design. A clean public CI checkout remains required.
