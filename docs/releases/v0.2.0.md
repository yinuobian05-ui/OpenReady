# OpenReady v0.2.0 release candidate

Status: local release candidate; publication is not yet authorized

The npm package, Git tag, and GitHub release do not count as published until each public endpoint is independently verified.

## Purpose

v0.2.0 lets a cautious first-time tester inspect real OpenReady output without first giving the tool access to personal repository files.

## One-command synthetic demo

Requirements: Node.js 20 or newer and a trusted local Git installation.

```sh
npx --yes "@yb5/openready@0.2.0" demo
```

`npx` may download the package before it starts. The demo then runs locally with no telemetry. It creates a unique operating-system temporary directory containing only fixed fictional files, initializes and stages a local synthetic Git repository with isolated Git configuration, scans it, and removes that exact directory.

The synthetic result is intentionally `BLOCKED`. The demo command exits `0` when setup, the expected scan, and cleanup all succeed; it exits `2` on a setup, scan, validation, or cleanup error. It does not accept a path or JSON mode.

## Real-repository scan

Run only from a repository you are authorized to inspect:

```sh
npx --yes "@yb5/openready@0.2.0" scan .
npx --yes "@yb5/openready@0.2.0" scan . --json
```

## Changes

- Add the no-argument `demo` command with a fixed, provider-neutral synthetic file set.
- Keep all demo files under one validated `mkdtemp` directory and clean that exact directory after success or failure.
- Ignore inherited Git configuration, identities, templates, hooks, and executable paths inside the launch directory or detected ancestor Git worktrees during demo setup and scanning.
- Keep matched values, Git identities, temporary absolute paths, inherited environment sentinels, and current-directory content out of output.
- Distinguish independent synthetic smoke tests from real-repository beta runs and adoption.
- Add macOS and Windows CI coverage alongside the existing Node.js 20, 22, and 24 Ubuntu jobs.

## Verification

- Local suite: 57 tests, 56 passed, 0 failed, and 1 platform-dependent filename test skipped because the current macOS filesystem rejected that filename.
- The demo returned its fixed `BLOCKED` result with 4 blockers, 5 warnings, and 1 informational boundary finding, then exited `0` after cleanup.
- Two concurrent demos used distinct temporary workspaces and left no entries in their test base.
- Package dry-run listed 23 intended files and created no tarball in the working tree.
- The source self-scan returned `READY` with 0 blockers, 6 warnings, and 4 informational findings; the warnings cover public Git identity review, unscanned history, and the three reviewed demo/social media assets.
- A fresh install from the local packed tarball reported version `0.2.0`; its demo completed with the expected result and cleanup, and its installed-package self-scan returned `READY` with 0 blockers, 0 warnings, and 1 informational finding.
- Public CI and closure of all remaining pre-release review items are required before publication.

No verified independent synthetic demo runner, real-repository user, feedback, adoption, review, or impact is claimed by this release at preparation time.

## Known limitations

- A synthetic demo run proves only that one person completed the fixed smoke test; it does not prove real-repository use or adoption.
- Historical Git file blobs are not scanned automatically. Use a maintained, history-aware secret scanner too.
- Ignored, untracked files are outside the Git repository scan set.
- Binary files, archives, databases, media, and Gitlinks are classified but not unpacked or parsed.
- Offline heuristics can miss secrets and can flag non-secrets; credentials are never checked with providers.
- OpenReady does not replace legal, copyright, license-compatibility, professional secret scanning, or human privacy review.
