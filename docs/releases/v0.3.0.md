# OpenReady v0.3.0 release candidate

Status: v0.3.0 release record. Candidate checks and public-release evidence are kept separate below.

## Why this change

An external reviewer correctly identified that v0.2.1 could inspect the working tree and current index yet still return `READY` when credential-shaped content existed only in an older commit. The reviewer did not run the package, so this is one attributable feedback item rather than an independent use report.

## Candidate behavior

- Enumerate objects reachable from all local Git refs and de-duplicate them by object ID.
- Scan bounded raw text blobs that are not already represented in the current index.
- Aggregate credential-shaped historical matches into one `OR-HIST-001` blocker at `.git/history`.
- Aggregate privacy-shaped historical matches into one `OR-HIST-002` warning at `.git/history`.
- Never expose historical filenames, lines, commits, object IDs, values, snippets, or Git identities.
- Reject shallow history and nonempty grafts instead of returning a partial history result.
- Reject linked worktrees, separate Git directories, and other unsupported `.git` layouts instead of returning a filesystem-only `READY` result without index or history coverage.
- Charge historical content against the existing entry, byte, and finding budgets while retaining the existing Git-output limit and per-command timeout.
- Report binary or over-limit historical blobs with `OR-BND-014` rather than claiming they were fully inspected.

## Boundaries

The candidate covers bounded raw text blobs reachable from local refs. It does not inspect unreachable or reflog-only objects, historical filenames, commit or annotated-tag messages, Git LFS payloads, submodule history, binary historical blobs, or historical blobs above the text-content limit. It remains a complementary pre-publication check, not a replacement for credential rotation or a maintained history-aware secret scanner.

## Release gate

Before v0.3.0 can be published, the complete test suite, package dry-run, source self-scan in a supported checkout, clean archive scan, fresh packed-package demo, and installed-package scan must pass. Public npm, tag, GitHub Release, and CI evidence must not be claimed until each is independently verified.

## Local candidate verification

Verified on 2026-09-03 without publishing:

- The complete suite reported 69 tests: 68 passed, 0 failed, and 1 platform-limited non-UTF-8 filename test skipped.
- The package dry-run listed 24 intended files and created no tarball in the working tree.
- A non-shallow local clone containing the complete existing OpenReady history plus the staged candidate returned `READY` with 0 blockers, 5 warnings, and 5 informational findings. The history boundary was reported as inspected.
- A temporary v0.3.0 tarball reported version `0.3.0`, completed the synthetic demo and cleanup, and returned `READY` with 0 blockers, 0 warnings, and 1 informational finding when scanning the unpacked package.
- `git diff --check` passed. Standard linked-worktree and separate-Git-directory regressions now prove those unsupported layouts fail closed with `GIT_METADATA_UNSAFE`; the isolated non-shallow clone remains the supported source-scan evidence.

At the time of this local candidate verification, public CI, commit, pull request, tag, npm staging, npm publication, and GitHub Release were unperformed and unclaimed. Any later public-release evidence must be verified and recorded separately.
