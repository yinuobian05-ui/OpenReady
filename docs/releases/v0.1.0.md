# OpenReady v0.1.0 release notes — draft

Status: public GitHub release candidate. The `main` branch is pushed to `yinuobian05-ui/OpenReady`; no version tag, GitHub Release, or npm publication exists yet.

## Summary

OpenReady v0.1.0 provides one offline, read-only command for reviewing a repository before it becomes public. It combines working-tree and current-index credential heuristics with privacy-path, email, Git author metadata, risky artifact, media, hygiene, and open-source governance checks.

## Included

- `openready scan [path]` and `openready scan [path] --json`.
- Stable blocker, warning, and informational findings.
- Exit code `0` for no blocker, `1` for blockers, and `2` for execution or usage errors.
- Always-redacted findings with relative paths and necessary line numbers only.
- No runtime dependencies, telemetry, remote access, credential verification, or file modification.
- Boundary reporting for symlinks, binaries, unreadable files, large content, Gitlinks, and non-Git directories.
- Separate checks for every bounded ordinary Git index blob and each indexed symlink target string, plus rejection of unsupported metadata redirects.

## Known limitations

- This release scans the current Git index, but does not scan secret content stored only in historical Git blobs.
- Ignored, untracked files are outside the Git repository scan set.
- Binary files, archives, databases, media, and Gitlinks are classified but not parsed.
- Text files larger than 10 MiB receive filename, type, and size checks only.
- Repositories that exceed fixed safety budgets exit `2` without a partial result.
- Offline heuristics can miss secrets and can flag non-secrets.
- The tool does not replace legal, copyright, license-compatibility, or human privacy review.
